## 1. What this project is

**EZ Trader Platform** is a simulated stock-trading web application built for IFT 401 (Team 41, Professor Michael Walsh). It lets customers trade stocks against a simulated market, and lets administrators create stocks and control when the market is open. All prices are generated by a custom random price generator — there is no real market data feed and no real money.

The app **must run locally** end to end: MySQL database + Express API + React front end, started from this repo with documented commands. Cloud deployment (AWS) is a later phase and must never be a prerequisite for running or grading the app locally.

## 3. Core domain rules

These are the requirements the grader cares about. Enforce them **server-side**; client-side checks are UX only.

### Market hours
- A trade executes only when the market is open.
- Open means: current time is between `opening_time` and `closing_time`, today is a configured trading weekday, and today is not a configured holiday.
- Admins can change opening/closing times, the trading weekdays, and the holiday list at runtime.
- Every order endpoint checks market status before anything else and returns a clear "market closed" error.

### Trading
- Orders are **market orders** executed at the stock's `current_price` at execution time.
- **Buy:** verify customer cash ≥ `quantity × current_price`. Debit cash, create/increase holding (recompute `average_cost`), write a transaction.
- **Sell:** verify holding `quantity` ≥ requested shares. Credit cash with proceeds, decrease holding (delete when it hits 0), write a transaction.
- Order status lifecycle: `PENDING` → `FILLED` | `CANCELLED`.
- A customer may cancel an order only while it is `PENDING`. A `FILLED` order can never be cancelled.
- Every trade runs inside a **single database transaction** (`sequelize.transaction()`) covering cash, holdings, orders, and transactions. Partial writes are a bug.

### Cash
- Deposits increase `balance`; withdrawals decrease it.
- A withdrawal above the available balance is rejected.
- Sale proceeds land in the cash account. Withdrawals come only from the cash account.
- Amounts are `DECIMAL(15,2)`. Never do money math in floats — use integer cents or a decimal library when computing, and always round to 2 dp before persisting.

### Price generator
- Runs on a schedule (every 30–60 s) **only while the market is open**.
- Each tick: for every stock, apply a small bounded random drift to the previous price (e.g. ±0–2%). Prices change gradually — never a single large jump.
- Clamp to a minimum positive price (e.g. `0.01`); prices must never go to or below zero.
- Per stock, maintain: `current_price`, `opening_price` (set once at market open each trading day), `daily_high`, `daily_low`, and append a `Price_History` row.
- `market_cap` is **derived**, not stored: `total_volume × current_price`.

### Roles
- `customer`: own account, cash, portfolio, orders, transactions.
- `admin`: create stocks, manage market hours/schedule. Admins do not trade.
- Enforce with middleware (`requireAuth`, `requireRole('admin')`) on every protected route. A customer must never be able to read or mutate another customer's data — scope every query by the authenticated `user_id`.

## 6. Database schema

From the team's approved ERD. Table and column names below are authoritative — match them exactly in migrations; use `underscored: true` in Sequelize so JS stays camelCase.

**Users** — `user_id` PK INT, `first_name` VARCHAR(50), `last_name` VARCHAR(50), `username` VARCHAR(50) UNIQUE, `email` VARCHAR(100) UNIQUE, `password_hash` VARCHAR(255), `role` VARCHAR(20) (`customer`|`admin`), `created_at` DATETIME

**Cash_Accounts** — `account_id` PK, `user_id` FK→Users (1:1), `balance` DECIMAL(15,2) default 0.00, `created_at`, `updated_at`

**Stocks** — `stock_id` PK, `ticker` VARCHAR(10) UNIQUE, `company_name` VARCHAR(100), `total_volume` BIGINT, `current_price` DECIMAL(15,2), `opening_price` DECIMAL(15,2), `daily_high` DECIMAL(15,2), `daily_low` DECIMAL(15,2), `created_at`, `updated_at`

**Holdings** — `holding_id` PK, `user_id` FK, `stock_id` FK, `quantity` INT, `average_cost` DECIMAL(15,2), `created_at`, `updated_at`; unique composite index on (`user_id`,`stock_id`)

**Orders** — `order_id` PK, `user_id` FK, `stock_id` FK, `order_type` VARCHAR(10) (`BUY`|`SELL`), `quantity` INT, `price` DECIMAL(15,2), `status` VARCHAR(20) (`PENDING`|`FILLED`|`CANCELLED`), `order_time` DATETIME, `filled_time` DATETIME NULL

**Transactions** — `transaction_id` PK, `user_id` FK, `order_id` FK NULL (null for deposits/withdrawals), `transaction_type` VARCHAR(20) (`BUY`|`SELL`|`DEPOSIT`|`WITHDRAWAL`), `amount` DECIMAL(15,2), `transaction_time` DATETIME

**Price_History** — `history_id` PK, `stock_id` FK, `price` DECIMAL(15,2), `recorded_at` DATETIME

**Market_Schedule** — `schedule_id` PK, `opening_time` TIME, `closing_time` TIME, `trading_date` DATE, `is_open` BOOLEAN, `holiday_name` VARCHAR(100) NULL

Associations: `User` 1–1 `CashAccount`; `User` 1–* `Holding`, `Order`, `Transaction`; `Stock` 1–* `Holding`, `Order`, `PriceHistory`; `Order` 1–* `Transaction`.

Schema changes go through a **new migration** — never edit an applied migration, and never rely on `sequelize.sync({ force: true })` outside of a throwaway dev database.

## 7. API surface

All JSON. Protected routes require a valid JWT cookie. Errors: `{ "error": { "code": "...", "message": "..." } }` with a correct HTTP status.

```
POST   /api/auth/register          create customer + cash account (txn)
POST   /api/auth/login
POST   /api/auth/logout
GET    /api/auth/me

GET    /api/stocks                 list w/ price, volume, market cap, open, high, low
GET    /api/stocks/:ticker
GET    /api/stocks/:ticker/history price history for charting

GET    /api/market/status          { isOpen, opensAt, closesAt, reason }

POST   /api/orders                 { ticker, orderType, quantity }
GET    /api/orders                 own orders, filter by status
DELETE /api/orders/:id             cancel if PENDING

GET    /api/portfolio              holdings + current values + cash + total value
GET    /api/transactions           own transaction history

GET    /api/cash                   balance
POST   /api/cash/deposit           { amount }
POST   /api/cash/withdraw          { amount }

POST   /api/admin/stocks           create stock (unique ticker enforced)
GET    /api/admin/stocks
PUT    /api/admin/market/hours     { openingTime, closingTime }
PUT    /api/admin/market/schedule  { tradingDays[], holidays[] }
```

Return money as strings or numbers rounded to 2 dp — consistently, one choice across the whole API.

## 8. Front-end pages (from approved wireframes)

1. **Create Account / Login** — name, username, email, password; validate required fields and username availability.
2. **Customer Dashboard / Portfolio** — cash balance, total portfolio value, holdings (shares + current value), and an available-stocks table showing company, ticker, current price, volume, market cap, opening price, daily high, daily low. Market open/closed indicator is always visible.
3. **Buy / Sell Stock** — pick stock, buy or sell, share quantity; shows current price, open/high/low, available cash, shares owned, estimated total, market status. Confirm before submitting.
4. **Orders & Transaction History** — pending orders with a Cancel action (hidden/disabled once filled), plus completed trades, deposits, and withdrawals.
5. **Cash Management** — balance, deposit/withdraw form, recent cash activity; block over-withdrawal with a clear message.
6. **Admin — Stock Management** — create stock (company, ticker, volume, initial price), list existing stocks, reject duplicate tickers.
7. **Admin — Market Settings** — opening/closing times, trading weekdays, holiday list.

Conventions: show loading and error states on every data view; disable submit buttons while a request is in flight; surface the API's error message rather than a generic one; poll `/api/stocks` and `/api/market/status` on an interval (e.g. 15 s) on the dashboard and trade pages so prices visibly move.

## 9. Coding conventions

- ESM `import`/`export` everywhere. No `require` in new files.
- `async/await` with a central Express error handler — no unhandled promise rejections.
- Validate and sanitize every request body server-side before it reaches a service.
- Never return `password_hash` in any response; use a model `defaultScope` that excludes it.
- Keep functions small and named for what they do (`executeBuyOrder`, `isMarketOpen`, `applyPriceDrift`).
- Comments explain *why*, not *what*. No commented-out code in commits.
- Money: `DECIMAL(15,2)` in MySQL, rounded to 2 dp before persisting, never compared with `===` after float math.
- Times: store UTC; convert for display. Market hours are evaluated in a single configured timezone (`America/Chicago`).

## 10. Testing & seed data

Seeders must produce a demo-ready database:

- 1 admin (`admin` / known dev password) and 2–3 customers with cash balances.
- 8–12 stocks with realistic tickers, company names, volumes, and starting prices.
- A market schedule open on weekdays, roughly 09:30–16:00, with one holiday row.
- Some price history so charts are not empty, plus a few filled orders and transactions.

Cover with tests at minimum: buy with insufficient cash is rejected; sell more shares than owned is rejected; withdrawal above balance is rejected; order placed while market closed is rejected; cancelling a filled order is rejected; a successful buy moves cash, holdings, orders, and transactions consistently; duplicate ticker creation is rejected.

Before saying a feature is done, run it: `npm run dev`, exercise the path in the browser, and confirm the database rows actually changed.

## 13. Non-goals

No real market data, no real money or payment processing, no limit/stop orders, no margin or short selling, no after-hours trading, no mobile app, no microservices. If a request seems to need one of these, flag it rather than building it.
